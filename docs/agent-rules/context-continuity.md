# 上下文连续性规则

- `docs/context.md` 只保存用户确认过的关键连续性信息：当前目标、仍有效的决定、已知阻塞、明确禁令和下一步。
- 系统历史表明发生上下文压缩后，继续任务前必须先读取 `docs/context.md`。
- 决定 Hook 语义、版本范围、验收标准、架构权威、发布状态或用户禁令前，先在 `docs/context.md` 搜索现有定义。
- 上下文压缩后如有新的重要连续性信息，先整理出准备写入的原文交用户确认；只有用户确认后才能追加。
- 已确认决定、当前观察、已知问题、禁止事项和下一步必须分开记录，不得把推测写成已确认事实。
- 新决定采用追加方式；旧决定失效时明确标记被哪条新决定替代，不静默改写历史。
- `docs/context.md` 应保持精简。实现细节、完整测试流程、教程、长篇复盘和可从专题规则恢复的信息不写入 context。
