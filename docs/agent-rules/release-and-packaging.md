# 构建、安装与发布规则

- 构建、安装、替换真实应用或发布必须在实现和前置验收通过后单独获得用户授权。
- 触发强制停止后，未经用户确认，不得构建、安装、替换 `/Applications/Blueberry.app`、推送或发布。
- 验证 macOS 安装包时，必须把关键 `app.asar` 文件与准确 worktree 在安装前后进行字节级比对。
- 清理或替换构建产物前先确认精确目标，保留可恢复路径，不使用破坏性 Git 或宽泛删除命令。
- 源码测试通过不证明安装应用包含相同代码；制品身份必须单独验证。
- 未签名、未公证、未完成安装运行时和包身份验证时，不得声称已经公开发布或可以安全分发。
- 发布记录必须区分：本地提交、远端分支、PR、合并到 main、GitHub Release、已安装应用和对外发布。

## macOS 审计脚本的命令路径规则

- 2026-08-08 阶段 4 重装首次尝试失败：脚本未经验证便假定 `realpath` 位于 `/usr/bin/realpath`、`test` 位于 `/usr/bin/test`。实际环境中前者由 `PATH` 从其他位置提供，后者的外部命令位于 `/bin/test`；脚本以 `exit 127` 在任何应用移动前停止。
- 根因是把“交互式 shell 能找到命令”错误等同于“该命令位于假定的绝对路径”。不得根据经验、其他 Unix 系统或先前环境猜测 macOS 可执行文件位置。
- 编写会执行移动、覆盖、安装、卸载或恢复操作的脚本前，必须先用只读命令探测所有外部依赖，例如 `command -v <name>`，并用 `test -x <resolved-path>` 验证解析结果；需要固定绝对路径时，只能使用本机探测并记录过的路径。
- 必须在首次有状态变化之前运行完整的只读预检，覆盖脚本实际引用的每一个外部命令，而不只是主要工具。预检结果、解析路径和退出码必须进入 transcript。
- `zsh -n` 只证明 shell 语法可解析，不能证明命令存在、路径正确、权限足够或运行语义符合预期；不得把语法检查当作环境兼容性验证。
- shell 内建命令与同名外部程序必须明确区分。若审计要求 transcript 展示固定工具来源，应记录 `type -a` 或 `command -V` 结果，并验证最终采用的实现。
- 任一命令路径或依赖验证失败时，必须发生在文件移动之前并立即停止；不得在同一轮中凭猜测替换路径后继续安装。
