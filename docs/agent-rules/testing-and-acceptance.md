# 测试、验收与证据规则

- 第一次有证据的修复仍失败时，保存失败测试、复现步骤、日志和 Git 状态，停止并询问用户。
- 验收门槛失败后不继续下游测试，不通过削弱、删除或改写验收要求获得 PASS。
- TDD 的失败阶段必须由目标行为缺失引起；实现后运行同一个聚焦测试证明转绿，再运行相关回归。
- 优先使用确定性测试和假时钟验证状态边界；运行态动画使用 CDP 检查 Renderer 状态，Computer Use 不作为并发或精确时间行为的唯一证据。
- HTTP 200 只证明事件被接受；单元测试只证明对应逻辑；截图只证明观察时刻；单轮运行不证明稳定性。
- 主 Agent 必须核对实际命令、退出码、测试数量、跳过项和原始输出。
- v1.1.0 必须分别通过自动化、worktree 运行时、真实单会话 Codex、安装运行时和制品身份门槛，才能声称完成或发布就绪。
- 多会话行为不属于当前确认的 v1.1.0 范围。
- 已知必需行为失败或缺少证据时，不得使用“完成”“接近完成”“已验收”“可发布”等表述。
